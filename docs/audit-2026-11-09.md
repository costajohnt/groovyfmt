# groovyfmt audit (2026-11-09)

groovyfmt @ commit `cecbdb0`, branch `main`, 2,544 tracked lines (src/lint.rs 558, src/main.rs 514, src/format.rs 362, tests/cli.rs 238, src/config.rs 150). Four parallel review streams (correctness, security, tests, architecture), with every Critical and High finding re-checked by a separate reviewer. Baseline on claude-worker: `cargo test --locked` passes 28 unit + 1 + 10 CLI tests (`test result: ok. 28 passed`, `ok. 1 passed`, `ok. 10 passed`); `cargo clippy --locked --all-targets -- -D warnings` clean; `cargo fmt --check` clean.

## Critical

## High

### H1. **The directory walk follows symlinks, so a symlink loop hangs the run**
`src/main.rs:159` `walk()` uses `Path::is_dir()`, which follows links, and recurses into every directory entry. Two committed links `a -> .` and `b -> .` make the walk branch at every level until the OS stops it at its symlink depth limit. A link to `/` walks the whole machine, and in write mode reformats any writable Groovy file it finds. Reproduced on claude-worker: `--check` on a directory with two such links hit the 10 s timeout (exit 124). Fix: read each entry's type with `DirEntry::file_type()`, which doesn't follow links, and don't descend into symlinked directories or read symlinked or non-regular files.

### H2. **A file name can inject GitHub Actions workflow commands in text mode**
`src/main.rs:331` and `:396`. `printable()` only escapes control characters, but a workflow command just needs a line that *starts* with `::`. Text mode prints the path at column 0, and the walker's `./` stripping (`:171`) puts a root-level file's name there. Reproduced: a file named `::warning title=PWNED::injected.groovy` made `--lint` print a line beginning `::warning title=PWNED::`. Config errors reach stderr through `die()` without any escaping (`:64-66`), and the runner reads stderr too. Fix: centralize escaping at the output sinks, prefix any line that would start with `:` with `./`, and run `die()` messages through `printable()`.

### H3. **Deeply nested input crashes `--lint` with a stack overflow**
`src/lint.rs:156-161` (`each`) and `:180-199` (`scan`) recurse once per tree level, and the parallel workers run on the default 2 MiB thread stack. Reproduced: 20,000 nested `[` aborted the process (exit 134), so neither the documented 0/1/2 exit codes nor any other file's results come out. `format.rs` already walks iteratively in `tokens()`. Fix: walk with a `TreeCursor` (iteratively) in both functions.

### H4. **Output grows quadratically with nesting depth, enough to exhaust memory**
`src/format.rs:93` and `indent_for` (`:199`). Indent grows by one step per nested row with no cap. At `indent = 16`, which a PR's own config can set, N lines of `(` followed by N of `)` produce on the order of 8·N² bytes. Reproduced: a 12 KB input of 3,000 nested parentheses ran past a 20 s timeout. This applies to `--check` too, since it builds the full output. Fix: skip files whose nesting exceeds a fixed depth, or whose output would grow beyond a small multiple of the input, as unformattable.

### H5. **`indent_after_labels` is cubic in block length**
`src/format.rs:192-196`. For each line, the label check walks every earlier sibling with `prev_named_sibling()`. In tree-sitter 0.26.13 that call itself re-walks from the parent's first child (`node.c:190-207`), so a block of k statements costs O(k³). The scan runs on every block, not just Spock methods, so a long Gradle `dependencies {}` block pays it too. Measured: a 20,000-line block takes 221 s with the option on and 0.24 s with it off (5,000 lines: 12.2 s vs 0.06 s). Fix: find each block's first label once and compare start offsets.

### H6. **The exit-2 CLI tests can't fail**
`tests/cli.rs:217-237`. The test writes an invalid `.groovyfmt.toml` first and never removes it, and only the first case checks stderr. The other four cases (`--bogus`, `--check --lint`, `--config nope.toml`, `--check missing.groovy`) would all still exit 2 from loading that bad config if the behavior each targets regressed. Verified by a second reviewer, which found `--config nope.toml` also masked. Fix: give each case its own directory and assert its specific stderr message.

## Medium

- **M1.** `src/format.rs:52-55`. The token-mismatch safety net is never exercised by a test. Verified reachable: mixed line endings (`"x = 1\r\ndef s = '''a\nb'''\r\n"`) rewrite the line ending inside the string, and the check correctly skips the file. A second reviewer refuted the suspected blind spot for string and comment interiors (single-quoted strings are one leaf, and mid-line whitespace is never touched). Fix: add that input as a regression test.
- **M2.** `src/format.rs:60`. One CRLF anywhere switches every line's ending to CRLF, so mixed-ending files with multi-line strings are always skipped. Fix: keep each line's own terminator.
- **M3.** `src/lint.rs:172`. Lint columns are byte offsets, so any multi-byte character earlier on the line shifts the reported column and the GitHub annotation. Fix: count characters in the line prefix.
- **M4.** `src/main.rs:169`, `:220`. Symlinked files and special files (FIFOs, `/dev/zero`) are read, and written through, with no size cap. A `/dev/zero` link reads until memory runs out. Fix: require a regular, non-symlinked file and skip files over a size cap.
- **M5.** `src/format.rs:187-198`. `indent_after_labels` treats any label (`outer:` before a loop) as opening a Spock block, which indents every later statement in the block (unverified). Fix: only Spock block labels count.
- **M6.** `src/lint.rs` throughout. About 25 node-kind and 12 field names are bare strings never checked against the grammar, so a renamed kind on the planned switch back to crates.io would silently turn a rule off (unverified). Fix: a unit test asserting each name exists in `LANGUAGE`.
- **M7.** `src/lint.rs:543-552`. `every_emitted_rule_is_registered` doesn't check that every rule fires. Fix: compare the set of emitted rule names with all of `RULES`.
- **M8.** `src/main.rs:325-329`, `:391`. `--check --output-format github` and `gh_escape` have no tests, and GitHub-mode messages skip `printable()`, so control characters other than CR/LF reach annotations. Fix: escape with both, and test the exact `::error` line.
- **M9.** `tests/cli.rs`. Write failures, read failures, discovery positives (Jenkinsfile, `.gvy`), config-name precedence, `--stats`, and the lint exemption cases (`ignore`, enum `;`, `+=` in a condition) have no tests (unverified).
- **M10.** `src/lib.rs:48-51`. `build`, `out` and `target` are skipped at any depth, including Groovy packages named `build` (unverified). Fix: an `exclude` config list, or only skip next to a build file.
- **M11.** `src/main.rs:141`. Config is found from the working directory, not from the files being formatted, and there's no `--stdin-filepath` for editors (unverified). Fix: discover per path argument, and add `--stdin-filepath`.
- **M12.** `src/lint.rs:256-261`. UnnecessarySemicolon would flag the `;` that is the empty body of `while (it.next());`, where removing it changes the program (unverified, depends on the grammar). Fix: exempt a `;` that is a loop or `if` body.

## Low (selected)

- `src/main.rs:208`: a panic in any worker aborts the run with exit 101 and writes nothing. Map it to a per-file error.
- `src/main.rs:326-331`: `groovyfmt --check | head -1` panics on a broken pipe.
- `src/main.rs:163-164`: unreadable directories are silently dropped. Report them and exit 2.
- `src/main.rs:321`: the in-place write truncates and then writes, so a crash mid-write can leave a truncated file. Use a temp file plus rename.
- `src/main.rs:81-133`: the hand-rolled parser accepts `--check=false` as on, has no `--` terminator, and silently ignores paths given with `--stdin`.
- `src/main.rs:352`, `:420`: skipped files never affect the exit code, so CI passes a file it couldn't check. Document it, or add `--strict`.
- `src/format.rs:73-161`: each line does several `parent()` lookups that re-walk from the root. Measured fine in default mode (0.24 s for 20,000 lines).
- `src/lint.rs:242-245`: `unnecessary_gstring` re-implements `has_interpolation()`.
- `src/format.rs:127`, `src/lint.rs:164`: `text()` is duplicated, and there are four separate tree walkers.
- `src/lib.rs:8-13`: a new `Parser` is built for every parse, 2 to 4 times per file.
- `.github/workflows/*.yml`: GitHub's own actions are pinned by tag rather than SHA, and `checkout` keeps its credentials.
- `.github/workflows/release.yml`: checksums live in the same release as the binaries, and there's no provenance attestation.

## Security summary

The tool runs in CI on pull-request content, so input is untrusted. Four issues let a PR disrupt that CI: a symlink loop hangs the run (H1), a crafted file name injects workflow commands into the log (H2), deep nesting crashes lint (H3), and deep nesting at a large indent exhausts memory (H4). All four were reproduced. Symlinked and special files are also read and written through (M4). The workflows themselves are sound: least-privilege permissions, third-party actions pinned by SHA, no `pull_request_target`, and a git dependency pinned to a full commit in both `Cargo.toml` and `Cargo.lock`. Note that a PR can always turn every lint rule off with its own config, so `--lint` alone isn't a trustworthy gate on untrusted PRs.

## Test quality

39 tests: 28 unit tests spread across the modules, 1 binary-level test, and 10 end-to-end tests that run the real binary in temp directories. The real-world safety check, formatting the 23.8k-file corpus twice and requiring no change, runs outside the suite. Gaps:
1. The exit-2 tests can't fail (H6).
2. The token-mismatch safety net is never exercised (M1).
3. Nothing checks that every rule fires (M7).
4. GitHub output for `--check` is untested (M8).
5. Write and read failures, discovery positives and lint exemptions are untested (M9).

## Refactoring map

1. Use one iterative preorder walker for every tree walk (fixes H3), and move `text()` into `lib.rs`.
2. Do escaping in one place at the output sinks (fixes H2 and M8).
3. Give file selection one policy: no symlinks, regular files only, a size cap, and reported read errors (H1, M4).
4. Pull the shared summary and skip bookkeeping out of the fmt and lint loops.

## Feature opportunities (ranked)

1. (S) `--stdin-filepath` for editors and per-path config discovery (M11).
2. (S) `--diff` in check mode. `Outcome::Formatted` already holds both texts.
3. (M) An `exclude` list in config, to replace the hardcoded directory names (M10).
4. (M) Autofix for UnnecessarySemicolon and UnusedImport, which needs a token check that allows declared removals.
5. (L) An LSP mode with range formatting. Indentation only depends on earlier rows, so ranges are cheap.

## Suggested first PR batch

1. The robustness fixes: H1, H2, H3, H4, H5, M4, plus the panic, broken-pipe and unreadable-directory Lows.
2. The test fixes: H6, M1, M7, M8, plus the M9 cases that cover code touched in batch 1.
3. The correctness fixes: M2, M3, M5, M12.
