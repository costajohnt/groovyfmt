# groovyfmt audit (2026-11-18)

groovyfmt @ commit `a0b43ca` (0.28.0), branch `main`, ~25,380 lines of Rust in `src/` (largest: main.rs 2355, lint.rs 2146, codenarc.rs 2016, wrap.rs 1806, lint/gradle.rs 1786). Five parallel review streams: correctness, security, tests, architecture, and README/docs accuracy. Every Critical and High finding was re-checked by a separate reviewer. Baseline on claude-worker: `cargo fmt --check` clean (`FMT_OK`); `cargo clippy --locked --all-targets -- -D warnings` clean; `cargo test --locked` passes all suites (`ok. 284 passed`, `ok. 12 passed`, `ok. 106 passed`, `ok. 2 passed; 0 failed; 1 ignored`, `ok. 12 passed`).

None.

## High

None. Two High findings were re-checked by separate reviewers. Both were confirmed but downgraded to Medium: the grammar-scanner robustness bugs (M19-M21) and the fixture-golden gap (M18).

## Medium

- **M1.** `README.md:68`, `docs/lint.md:3`, `docs/coverage.md:53`: the rule counts are stale. The README and lint.md say "82 rules, 58 on by default", and coverage.md says "56 are". The `RULES` registry in `src/lint.rs` has 84 rules, 60 of them on by default. The count is typed by hand in three places and no test ties it to `RULES`. Fix: "84 rules, 60 on by default", plus a test that checks the docs number against `RULES.len()`. (unverified)
- **M2.** `README.md:42`, `docs/usage.md:17`, `docs/agents.md:17-18`, `src/main.rs:88-90` (`--help`): `--lint --fix` is described as fixing imports and semicolons only. In fact 12 rules are fixable, including GradleRemovedConfiguration (rewrites `compile`), GradleJcenter, GradleLeftShiftTask and GradleSpaceAssignment. That summary predates the Gradle fixes. Fix: describe `--fix` as fixing the rules marked fixable, and link `lint.md#fixing`. (unverified)
- **M3.** `src/lint.rs:715`: GradleRemovedApi is marked `fixable: false`, so `--explain` prints "Not fixed automatically." But since 0.28.0, `--fix` rewrites the `groovy.util` XmlSlurper/XmlParser/FileNameFinder imports, and `docs/lint.md` documents that. A single `fixable` bool can't express a partial fix. Fix: give rules a partly-fixable state, or a note that `--explain` prints, and add the Groovy 4 moves to the rule's description. (unverified)

- **M4.** `--lines` and LSP rangeFormatting mishandle files with classic-Mac (lone `\r`) line endings.
  - Location: `src/diff.rs:159` (`format_lines`), reached from `src/main.rs:865` and `src/lsp.rs:468`.
  - Root cause: `format()` (`src/format.rs:79-84`) is the only entry point that converts a CR-only file to `\n` and back. `format_lines`/`format_rows` skip it, so the file reads as one line. `reindent` then appends `\n` and the trailing `\r` is trimmed. The token check passes because both changes are whitespace.
  - Reproduced: `def f() {\rx()\r}\r` with `--lines 1-1` produces `def f() {\rx()\r}\n`, so the result has mixed line endings and nothing is re-indented.
  - Fix: do the lone-`\r` conversion in `format_with`, so every entry point gets it.

- **M5.** `tests/fixtures.rs:33`: the fixture "whitespace-only" check deletes all whitespace before comparing. A regression that changes whitespace inside a string literal (`'''a\n b'''` becoming `'''a\nb'''`), or that joins tokens (`a - -b` becoming `a --b`), would still pass. So the check isn't independent of the in-product token guard. Fix: compare `format::tokens()` of the input and the output. (unverified)
- **M6.** `tests/fixtures.rs:168`, `scripts/ci-local.sh:94`: the corpus checks (mutation, fix-then-format settling, `--stats` idempotence) are still `#[ignore]` or run only when a corpus dir is passed, and CI runs neither. This repeats a finding from the prior audit. Fix: give ci-local.sh a default corpus path on claude-worker and run them unconditionally. (unverified)
- **M7.** `tests/cli.rs:3818`, `:3841`: two baseline-containment tests can't fail. They assert only exit 2, against baselines that don't exist, and a missing baseline already exits 2. Removing the `..` check (`config.rs:145`) or the `baseline::confined` call (`main.rs:1371`) leaves both green. The LSP test at `tests/lsp.rs:886` never reaches `lsp.rs:319` either. Fix: create the target files and assert the specific stderr text. (unverified)
- **M8.** `src/lint/elsewhere.rs:199`, exercised by `tests/cli.rs:1478` and `:4076`: project-root discovery walks up to `/`. A stray `.git` or `.groovyfmt.toml` in `/tmp` makes concurrently running tests see each other's files. The 10 MB `Big.groovy` would then trip the cap and silence the UnusedPrivate* rules. Fix: put a `.git` marker in each test dir, plus a guard test that no ancestor of `temp_dir()` holds one. (unverified)
- **M9.** `src/diff.rs:159`: no fixture, CLI test or LSP test contains a `groovyfmt: off` region. So the whitespace-only, idempotence and fix-settling invariants never run through the `format_lines` path. Fix: add a fixture with off/on regions (nested, unterminated, inside a closure), plus one CLI case. (unverified)

- **M10.** `src/lsp.rs:391`, `:498`: the editor's diagnostics differ from `--lint`.
  - Publish never calls `lint::opt_in_fixes`, so with `gradle_compile_replacement` set the editor still shows the generic GradleRemovedConfiguration message.
  - Code actions run a third variant, with no `spec_base` and no `projects.filter`.
  - Root cause: there is no single "lint under this config" function. The CLI (`main.rs:1432-1490`), LSP publish, LSP code actions and `fix::fix` each rebuild the chain by hand.
  - Fix: add `lint::run(path, src, cfg, projects, baseline)` and route all four callers through it. (unverified)
- **M11.** `src/main.rs` (2366 lines) holds all the I/O policy: walk, config resolution, atomic writes, git, output sinks, and the dev modes. The baseline lookup and `line_of` are duplicated in `lsp.rs`. Fix: move walk, write and output into lib modules. (unverified)
- **M12.** `src/main.rs:109-110`, `:797`: `github: bool` plus `machine: Option<Machine>` together encode four output formats, and the GitHub lines are built inline at six call sites. Fix: one `OutputFormat` enum, with the GitHub emitter in `report.rs`. (unverified)
- **M13.** `src/lint.rs:23-790`: the rule metadata is a 770-line table far from the rule code, with four dispatch mechanisms, and about 15 rule bodies sit in the registry file. Fix: give each module a `RULES` slice, and move the bodies to `lint/general.rs`. (unverified)
- **M14.** `src/lint/gradle.rs:83-490`: `check` is one ~400-line closure carrying about 12 state vectors. The file doubled from 0.21 to 0.28, reaching 3333 lines. Fix: one pass that collects a `GradleCtx`, with per-concern modules. (unverified)
- **M15.** `src/lint/gradle.rs:929`, `:1547`: `nearby` and `wrapper_version` re-read and re-parse sibling scripts and wrapper files on every file, up to 4 times each. `elsewhere::Projects` already has a per-root cache. Fix: move both into `Projects`. (unverified)
- **M16.** `src/config.rs:109-114`: an unknown rule name in `[lint]` is a hard error. So a config enabling a new rule breaks every older binary that reads it (pinned Action, Gradle plugin, editor, a teammate's brew). Fix: error only on near-misspellings, and warn otherwise (error under `--strict`). (unverified)
- **M17.** The platform-to-target table and the download/verify logic are reimplemented six times: `editors/vscode/src/binary.ts:15`, `editors/jetbrains/.../Binary.kt:32`, `gradle-plugin/.../Provisioner.java:54`, `npm/build.mjs:19`, `action.yml:44`, `packaging/homebrew/render.sh:18`. Fix: a release manifest JSON, plus a CI check against the build matrix. (unverified)

- **M18.** `tests/fixtures.rs:300-301`, `:373`: the 63 fixtures are not goldens. Verified.
  - What the tests check: `check` asserts only that the output is whitespace-only (`:33`) and idempotent (`:35-38`). `:300` discards the fixture's own formatted output, so `format(f) == f` is never asserted. `:301` compares `format(scramble(f))` only against the scrambled input.
  - Gap: a reindenter that consistently mis-indents a construct found only in the fixtures (`grammar_batch*`, switch/case, Spock labels, Jenkinsfiles) passes. Common constructs are pinned by 34 exact-output unit tests in `format.rs` and about 75 indentation literals in `tests/cli.rs`.
  - The specialist rated this High. The verifier lowered it to Medium, as a coverage gap rather than a shipped defect.
  - Fix: assert `format(scramble(f)) == format(f)` and `format(f) == f` for the canonical fixtures.

- **M19.** Deeply nested GString interpolation in a `pipeline` block aborts the whole run.
  - Location: `grammar/scanner.c:285` (`skip_braces`), with the recursion at `:335`, reached only from the `pipeline` branch at `:1430`.
  - Root cause: each `${` inside a double-quoted string recurses with no depth cap. `par_map` (`src/main.rs:525`) runs files on scoped threads with the default 2 MB stack, and a stack overflow is an abort, so the `catch_unwind` at `:533` can't contain it. Every file's results are lost.
  - Reproduced: `pipeline { x = "` followed by `${"` x40000 exits 134 (`thread '<unknown>' has overflowed its stack`), even with a good file alongside. A release build's frames are larger (80 B at -O3 vs 64 B), so it overflows sooner, at roughly 75 KB.
  - The LSP runs this on the main thread. On Windows that thread is 1 MB, so it should overflow around 12k nests (inferred).
  - Fix: a depth cap, or iterate with an explicit stack.
- **M20.** The `pipeline` lookahead at `grammar/scanner.c:1430` has no step budget, unlike `bracket_then_colon` at `:474` with its 4000-step cap.
  - Reproduced: `pipeline {\n` xn takes 0.87 / 3.43 / 13.6 s at n = 2000 / 4000 / 8000 (debug). The control `foo {` is linear.
  - Valid code triggers it too. `skip_braces` doesn't know slashy strings, so `pipeline { x = /{/ }` xn parses cleanly and is quadratic (1.7 / 6.7 s).
  - Fix: a shared step budget in `skip_braces`.
- **M21.** `skip_parens` lookahead is unbounded at `grammar/scanner.c:1083` (command-argument call), `:912` (dimension annotation) and `:962` (spaced call open).
  - Reproduced: `p.accept f(` xn takes 0.86 / 3.37 s. `def x = new int @A(` xn takes 1.66 / 6.08 s.
  - Valid code triggers it too. `skip_parens` takes the `'` inside a slashy string as a string start, so `p.accept f(/'/)` and `foo (/'/)` parse cleanly and are quadratic (1.37 / 5.23 s).
  - `skip_parameter_parens` (`:388`) is not affected.
  - Real-world exposure is mostly in editors: the LSP re-parses on every change, so a few-hundred-KB file can hang it.
  - Fix: the same shared step budget inside `skip_parens`, and teach both skippers about slashy strings or give up on `/`.
- **M22.** A compromised dependency in another release job could substitute the published binaries.
  - Location: `.github/workflows/release.yml:70-72`, plus the same pattern at `:242` (publish-npm) and `:277` (publish-image).
  - Root cause: these jobs run `download-artifact` with `merge-multiple: true` and no name or pattern, then publish `groovyfmt-v*.tar.gz*` / `*.zip*`, including the `.sha256` files, from the merged pool. The vscode job runs `npm ci` without `--ignore-scripts` (`:47`).
  - Attack path: a malicious install script that scraped `ACTIONS_RUNTIME_TOKEN` from runner memory (the tj-actions technique) could upload an extra artifact with identically named archives and checksums. The `test "$#" -eq 5` count check wouldn't notice. That widens a compromised editor dependency into the core binaries on GitHub, npm and GHCR.
  - Difficulty is high, but the fix is cheap: download by explicit artifact name, and add `--ignore-scripts` to the vscode `npm ci`.

## Low (selected)

- `src/format.rs:199,588`, `src/fix.rs:397,412`, `src/diff.rs:172-176`: four variants of the whitespace-only safety check. The formatter's version ignores field roles; the fixer's catches them. Fix: one `equiv` module. (unverified)
- `src/format.rs:85`, `src/diff.rs:159-185`: range and off-region formatting live in `diff.rs`, which creates a format→diff→format cycle. Fix: move them into `format`. (unverified)
- `src/wrap.rs:117-140`: the wrap fallback is reported through a thread-local, and the LSP, stdin and fix callers never clear it. Fix: carry the note in `Outcome`. (unverified)
- `src/lint.rs:952-962`, `src/syntax.rs:323-339`, `src/lsp.rs:211`: column conversion is done three ways. Fix: treat byte spans as canonical and convert once at the output edges. (unverified)
- `src/main.rs:173`: `std::env::args()` panics on a non-UTF-8 argument, such as a Latin-1 file name from `xargs`. Fix: use `args_os()`. (unverified)
- `src/main.rs:1481`, `:1547`: the `rule_enabled` filter runs twice. (unverified)
- `src/lib.rs:1-14`: every module is `pub` on crates.io, so any refactor is a semver break. Fix: mark them `#[doc(hidden)]`, or narrow to a facade. (unverified)
- `src/json.rs`: a hand-rolled JSON reader and writer, although tree-sitter 0.26 already pulls in `serde_json`. (unverified)

- `src/lint/gradle.rs:3097-3106`: the "wrapper pins Gradle 6" case can't fail, because the source has no Java plugin and so is unfixable regardless. Fix: prefix `apply plugin: 'java-library'`. (unverified)
- `tests/cli.rs:983`: the `compile/build.gradle` "keep" case can't fail, because `gradle_compile_replacement` is unset. Fix: write that config into the subdirectory. (unverified)
- `tests/cli.rs:3788-3790`: the check that secret.json isn't echoed asserts only that TOPSECRET is absent, so an early unrelated failure passes. Fix: remove the leftover config, and assert exit 2 and the error text. (unverified)
- `src/lint/elsewhere.rs:25-26`: the MAX_FILES and MAX_BYTES caps that silence UnusedPrivate* have no test. Fix: pass the caps into `Index::build` and unit-test them with tiny limits. (unverified)

- `src/lint/gradle.rs:416-428`: GradleRemovedApi's `--fix` inserts an import ending in a bare `\n` into a CRLF build script, because the inserted text is hard-coded. `fix::check` ignores line endings, so the mixed endings get through. Reproduced via od. Fix: use the line ending of the line at the insertion point.
- `src/lint.rs:947-958`, `:1011-1017`: a UTF-8 BOM shifts every line-1 column by one. `own_lines` also never counts a line-1 import as alone on its line, because `trim()` doesn't treat U+FEFF as whitespace, so the unused-import fix is skipped. Reproduced: `1:2: UnusedImport`, and `would fix 0 violations`. Fix: skip a leading BOM in both places.

- `docs/output-formats.md:29`: the JSON example's `summary` omits the `"fixed"` key, which `src/report.rs:110` always emits. (unverified)
- `docs/coverage.md:5,10-21`, `README.md:23`: the corpus numbers and the "still fails" list predate 0.20 through 0.27. For example, multiple assignment in a `for` header now parses. The README's corpus list also omits groovy and CodeNarc. Fix: re-measure at 0.28.0 and date the measurement. (unverified)
- `README.md:22`: the spock benchmark (0.19 s) was measured on 0.5.x and is stated as current. Fix: re-measure, or label the version. (unverified)
- `docs/releasing.md:143-155,172-181`: the Homebrew section and "Going public" read as pending launch steps, but the repo and the tap have been public for a while. (unverified)
- `docs/usage.md:26-41`: the options table omits `-V/--version` and `-v/--verbose`, which `--help` lists. (unverified)
- `docs/agents.md:43`: the Claude Code hook's file pattern misses `Jenkinsfile.deploy`, `*.jenkinsfile` and `*.jenkins`, all of which groovyfmt picks up. (unverified)
- `editors/vscode/README.md:13`: doesn't say how to install the `.vsix` until the extension is on Open VSX, or that it isn't there yet. The extension is on the VS Code Marketplace as of 0.28.0, so recheck before editing. (unverified)
- `src/config.rs:340` (`Resolver::find` uses `is_file()`) and `:162`: a committed `.groovyfmt.toml` symlink is followed outside the repo and read with no size cap. Reproduced with a link to `/etc/os-release`, which gave a TOML parse error, exit 2. This is inconsistent with `baseline::confined()`. Fix: use `symlink_metadata`, or confine the path, and cap the read at `MAX_FILE_BYTES`.

### README readability

A Gradle or Jenkins user landing on the README can't tell what the formatting looks like. Gaps:
- There is no before/after code sample.
- It never says the formatter re-indents only, with spacing and wrapping opt-in.
- There is no comparison with Spotless (greclipse) or npm-groovy-lint.
- The Gradle 9 / Groovy 4 rules, the strongest hook for this audience, appear only as "mistakes that otherwise surface only when a build runs".

The Linting paragraph and the Install paragraph are dense. The file list omits `.gvy/.gy/.gsh`, and the README doesn't say that `build.gradle.kts` is out of scope.

## Security summary

Output injection, path confinement, LSP framing and URI handling, action.yml input handling, SHA-pinned workflow actions, and checksum-verified downloads in every channel are all clean. The prior audit's `::`/`##[` injection and symlink findings stay fixed.

What remains exposed:
- Untrusted-input robustness in the C scanner: M19 aborts the process, and M20/M21 are quadratic. All three fail closed (crash or slowness), with no integrity impact, but they can crash-loop the LSP.
- One supply-chain hardening gap in the release workflow (M22).
- A config symlink followed outside the repo (Low).

## Test quality

Discipline is strong: 418 tests, every rule with positive and negative lines, and every fixable rule with a fix test plus a second-pass no-op assertion. The token guard has injected-bad-output tests, and a registry test ties `RULES` to the emitted rules. Idempotence was swept 248 ways with no failures. Gaps:
1. The fixtures are not goldens (M18).
2. The fixture whitespace check isn't independent of the token guard (M5).
3. The corpus mutation and `--stats` checks never run in CI (M6).
4. The baseline-containment tests can't fail (M7), and three Low cases can't either.
5. Tests depend on what exists above `/tmp` (M8).
6. `groovyfmt: off` regions never go through the whole-file invariants (M9).
7. The scanner has no pathological-input tests (M19-M21).

## Refactoring map

1. One lint pipeline, `lint::run`, used by the CLI, LSP publish, LSP code actions and `fix` (M10, plus the double-filter Low).
2. An `OutputFormat` enum, with the GitHub emitter in `report.rs` (M12). This unlocks Checkstyle and GitLab output.
3. Move the lone-`\r` conversion into `format_with` (M4), and range/off formatting into `format` (Low).
4. One `equiv` module for the token/shape checks (Low).
5. A Gradle cross-file cache in `Projects` (M15), then split `gradle.rs` around a `GradleCtx` (M14).
6. Per-module `RULES` slices, with rule bodies out of `lint.rs` (M13).
7. Lib modules for walk, write and output, slimming `main.rs` (M11). Mark the lib `#[doc(hidden)]` first (Low), so refactors aren't semver breaks.
8. A release manifest consumed by all six download clients (M17).
